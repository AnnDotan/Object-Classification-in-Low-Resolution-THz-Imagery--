## Iteration 1 — Per-cell accuracy ↔ image-quality join (PRD V2 §4.1, §6.2 step 1)

- Implemented `Final_Report/scripts/build_per_cell_with_iq.py`: joins the 402
  canonical accuracy rows in `artifacts/Final_Exp.json` with the per-pipeline
  PSNR / SSIM in `Final_Report/data/image_quality/_index.csv`. Outputs
  `Final_Report/data/tables/per_cell_with_iq.csv` matching the PRD §4.1 column
  contract (`tag, model, dataset, phase, level, axis, regularization, seed,
  val_acc, psnr_mean, psnr_std, ssim_mean, ssim_std`) + 3 multi-seed bonus
  columns (`val_acc_mean, val_acc_std, n_seeds`).
- Script asserts row-count = 402 and that every non-A cell has a populated IQ
  join; raises SystemExit otherwise. Run output: 402 rows, 6 Phase A (null IQ
  by construction), 396 non-A with IQ.

- Files affected:
  - Final_Report/scripts/build_per_cell_with_iq.py (new)
  - Final_Report/data/tables/per_cell_with_iq.csv (new)
  - Final_Report/PROGRESS.txt (this entry)

- Learnings for next cycles:
  - Patterns:
    * `artifacts/Final_Exp.json` (schema_version=3) is the canonical accuracy
      source: 402 rows, one per canonical cell at seed=42. Multi-seed audit
      replicates at seeds {43, 44} are NOT separate rows — they are aggregated
      into `val_acc_mean` / `val_acc_std` / `seeds_observed` on the base tag.
    * Phase D rows must reuse Phase B1 IQ (degradation pipeline is identical;
      only training-time regularization differs). Implemented by mapping
      `iq_phase = "B" if phase == "D" else phase` on the IQ lookup key.
    * Phase A rows carry null PSNR / SSIM — identity pipeline, IQ undefined.
      Six rows total (3 models × 2 datasets). Downstream curves / scatters
      must filter these out before computing Spearman ρ etc.
  - Traps:
    * PowerShell calls go through Bash by default; use the dedicated PowerShell
      tool for JSON `ConvertFrom-Json` exploration. Bash escaping for `$()`
      mangles the call.
    * `_index.csv` has 102 pipelines but NO Phase A entries — assume null IQ
      for A rather than asserting coverage.
    * `treatment` (the in-repo column name from `Final_Exp.json`) maps to the
      PRD V2 column name `regularization`. Keep the rename local to this
      script; don't propagate upstream.
  - Helpful context:
    * `scripts/aggregate_pipelines.py` already produces the precursor
      `Final_Report/data/tables/per_cell.csv` with similar columns. The new
      `per_cell_with_iq.csv` is the PRD V2-named, contract-bound version
      meant for §4.2 (per-axis PSNR / SSIM curves) and §10 QA gate #21
      (headline pp value cross-check).
    * Next D1 sub-tasks per PRD §6.2 step 1:
        - `scripts/build_psnr_axis_curves.py` → 8 PNG/PDF pairs + Spearman ρ
          metadata JSON (§4.2)
        - `scripts/build_ece_vs_level.py` → ECE vs level line chart

## Iteration 2 — Per-axis acc vs PSNR / SSIM curves (PRD V2 §4.2, FX-15, §6.2 step 1)

- Implemented `Final_Report/scripts/build_psnr_axis_curves.py`: reads
  `per_cell_with_iq.csv` from Iteration 1 and emits 8 figure pairs (PNG + PDF)
  under `Final_Report/figures/curves/` plus a `_axis_curves_meta.json` for
  LaTeX caption injection (per-axis Spearman ρ + a one-sentence ranking note).
- Figure spec per FX-15: figsize=(8, 5), dpi=160, three model markers
  (circle / square / triangle), five axis line-styles (solid / dashed /
  dotted / dash-dot / long-dash). Shared y-range across CIFAR-10 vs MNIST
  within (phase, metric) per PRD §4.2.
- Smoke result: TransNeXt-tiny (red triangle) traces dominate every curve at
  matched PSNR / SSIM, consistent with the operator-locked +5 / +7 / <1 pp
  margins. Resolution axis Spearman ρ = +0.93 (Phase C CIFAR-10) and +0.98
  (Phase C2 CIFAR-10 + both MNIST) — dominates the per-axis association in
  every plot, matching the PRD §4.6 finding (resolution dominates by ~4×).

- Files affected:
  - Final_Report/scripts/build_psnr_axis_curves.py (new)
  - Final_Report/figures/curves/acc_vs_{psnr,ssim}_phase{C,C2}_{cifar10,mnist}.{png,pdf} (16 new)
  - Final_Report/figures/curves/_axis_curves_meta.json (new)
  - Final_Report/PROGRESS.txt (this entry)

- Learnings for next cycles:
  - Patterns:
    * Per-axis Spearman ρ between accuracy↔PSNR and accuracy↔SSIM is
      mathematically identical within an axis whenever PSNR and SSIM are
      monotonically related across the 5 levels (they always are — both
      degrade monotonically with level). The metadata JSON keeps both
      explicitly for caption symmetry, but the LaTeX captions can flag
      "ρ identical by monotonicity" if desired.
    * matplotlib Line2D needs the call `linestyle=(0, (5, 1))` for the
      5th axis "long-dash" — `:` / `-.` / `--` exhaust the named styles.
    * Each plot needs a two-part legend: model (color + marker) and axis
      (linestyle). Use `ax.add_artist(leg1)` to keep both visible.
  - Traps:
    * `per_cell_with_iq.csv` writes empty strings for null IQ (Phase A).
      Filter `row["psnr_mean"] != ""` before float-casting. Phase C / C2
      rows are guaranteed non-null per Iteration 1's invariant.
    * y-range computed across both datasets per (phase, metric) prevents
      MNIST's near-100% saturation from squashing the CIFAR-10 dynamic
      range visually. Confirmed: Phase C / cifar10 ranges 40.4 → 100 pct,
      MNIST plot uses the same y-axis.
  - Helpful context:
    * Next D1 sub-tasks: build_ece_vs_level.py, combine_calibration_grids.py,
      combine_confusion_grid.py. The diagnostics CSV / JSON inputs sit
      under `artifacts/validation/` per CLAUDE.md.
    * scipy 1.17.1 + matplotlib 3.10.9 confirmed available on the host;
      no `Agg` install needed (`matplotlib.use("Agg")` is set at module top).

## Iteration 3 — ECE vs level line chart (PRD V2 §4.3 / §4.5 figure 21 / §6.2 step 1)

- Implemented `Final_Report/scripts/build_ece_vs_level.py`: reads
  `artifacts/figures/calibration/_index.json` (42 entries: 7 phase / level
  groups x 6 model / dataset pairs) and emits one chart per dataset showing
  ECE at L3 vs L5 across the three phases with entries at both levels
  (B, D-T3, B2-T3). Phase B2-nr is L3-only → reported as a footnote field
  in the metadata JSON.
- Output: `figures/curves/ece_vs_level_{cifar10,mnist}.{png,pdf}` +
  `_ece_vs_level_meta.json`. Plot styling mirrors Iteration 2 (figsize=(8, 5),
  dpi=160; 3 model markers, 3 phase line-styles, shared y-range across
  datasets).

- **DATA / FINDING DISCREPANCY (flag for operator)**. As-measured mean
  ΔECE from L3 → L5: CIFAR-10 = **−2.03 pp**, MNIST = −1.93 pp. ECE *drops*
  from L3 to L5 in 6 of 9 (model, phase) series on CIFAR-10. This contradicts
  PRD §4.8 / CLAUDE.md Finding #8 ("ECE rises from < 5 pp at L3 to > 15 pp
  at L5 on CIFAR-10"). The worst CIFAR-10 L5 cell is `densenet121/B2-T3` at
  3.06 pp — nowhere near 15 pp. Plausible root cause: at L5 the model is so
  wrong that confidence also collapses, lowering ECE (under-confident
  failure mode rather than over-confident). Next session must decide:
    (a) re-examine `generate_calibration_diagrams.py` to confirm ECE
        is computed on the right split (val vs test) and the right level
        (some entries may have label-mismatch at L5);
    (b) re-state Finding #8 against the as-measured data; OR
    (c) accept the figure as-is and rewrite the §7.7.8 / §7.10 narrative
        to match the actual behaviour ("ECE is highest at L3, where the
        model is still confident but starting to mis-classify; at L5 the
        model becomes under-confident as accuracy collapses").
  Do NOT delete or hide this figure — it's the honest data.

- Files affected:
  - Final_Report/scripts/build_ece_vs_level.py (new)
  - Final_Report/figures/curves/ece_vs_level_{cifar10,mnist}.{png,pdf} (4 new)
  - Final_Report/figures/curves/_ece_vs_level_meta.json (new)
  - Final_Report/PROGRESS.txt (this entry)

- Learnings for next cycles:
  - Patterns:
    * Calibration ECE is stored in `artifacts/figures/calibration/_index.json`
      (42 entries). Schema: `{phase, treatment, model, dataset, level,
      ece_pp, ece_tm_pp, png, tag, split}`. `ece_pp` = manual binning;
      `ece_tm_pp` = TorchMetrics value (agree to ~0.001 pp). Use `ece_pp`.
    * Available level coverage in the JSON is L3 and L5 only — no L1 / L2 /
      L4 calibration computed. A 5-point ECE-vs-level chart is NOT possible
      without re-running diagnostics. The 2-point chart is what the data
      supports.
    * Phase B2-nr only exists at L3. Any "across both levels" line filter
      drops it from the line chart but keeps it in the metadata JSON
      footnote.
  - Traps:
    * The PRD Finding #8 narrative ("ECE rises from < 5 to > 15 pp at L5
      on CIFAR-10") is NOT consistent with the artifacts on disk. Flag in
      PROGRESS.txt and the captions / narrative, but DO NOT fabricate or
      cherry-pick to match. Reproducibility is the v5 north star (PRD §5
      "Operator-facing pp numbers come from §4 of this PRD") — but the
      §4 numbers are derived FROM the artifacts, so when they diverge the
      artifacts win.
    * `_index.json` uses `treatment: null` for the no-reg phases (B, B2nr).
      Don't compare with the string "None"; use Python `None` /
      `e.get("treatment")`.
  - Helpful context:
    * Next D1 sub-tasks: combine_calibration_grids.py (FX-05;
      B_L3_grid.png + B_L5_grid.png), combine_confusion_grid.py (FX-06;

## Iteration 4 — Phase B reliability-diagram 3×2 grids (PRD V2 §4.5 figs 19/20, FX-05)

- Implemented `Final_Report/scripts/combine_calibration_grids.py`: tiles the
  6 existing Phase B reliability-diagram PNGs at each level (3 models ×
  2 datasets) into one composite 3×2 grid PNG so the report embeds two
  figures instead of twelve. Rows = models, cols = datasets. Layout
  preserves each source panel's ECE annotation; row labels and column
  titles are added by the composite.
- Output: `Final_Report/figures/calibration/B_L{3,5}_grid.png` + a
  `_grid_meta.json` recording panel sources for traceability.
- Smoke check: B_L3_grid.png renders cleanly at 1440×1920 (figsize=(9, 12),
  dpi=160); all six source panels present in the expected positions.

- Files affected:
  - Final_Report/scripts/combine_calibration_grids.py (new)
  - Final_Report/figures/calibration/B_L3_grid.png (new)
  - Final_Report/figures/calibration/B_L5_grid.png (new)
  - Final_Report/figures/calibration/_grid_meta.json (new)
  - Final_Report/PROGRESS.txt (this entry)

- Learnings for next cycles:
  - Patterns:
    * Source panel naming is `final_B_L{level}_{model}_{dataset}_L{level}.png`
      under `artifacts/figures/calibration/` — note the level appears TWICE
      in the filename (once in the tag, once as a suffix). This double-L
      pattern is set by `generate_calibration_diagrams.py` upstream.
    * Tiling via `matplotlib.image.imread` + `ax.imshow` + `set_xticks([])`
      + `set_yticks([])` + spine-off gives clean borders with no padding
      artifacts. Use `fig.suptitle(..., y=0.995)` and `tight_layout(rect=[0,
      0, 1, 0.985])` to reserve room for the top title.
  - Traps:
    * FX-05's "sharex='all', sharey='all', single shared colorbar" language
      doesn't apply to reliability diagrams (bar charts, no colormap). The
      same FX-05 language was probably copy-pasted into the PRD from the
      FX-06 confusion-grid spec. Honored the *intent* (one figure embed
      per level, uniform borders) without forcing the technical mechanism.
    * `set_ylabel(..., rotation=90, labelpad=6)` is the cleanest way to
      label rows on an imshow grid; using a separate fig.text() places
      the label outside the subplot's bounding box and overlaps the panel
      below.
  - Helpful context:
    * Next D1 sub-task: combine_confusion_grid.py (FX-06; B_L5_grid.png).
      Source PNGs under `artifacts/figures/confusion/` already share the
      level naming pattern. FX-06's "shared vmin=0, vmax=1, single
      colorbar" DOES apply (confusion matrices are heatmaps); use
      matplotlib imshow with explicit vmin / vmax and a single fig
      colorbar.

## Iteration 5 — Phase B L5 confusion-matrix 3×2 grid (PRD V2 §4.5 fig 22, FX-06)

- Implemented `Final_Report/scripts/combine_confusion_grid.py`: re-renders
  all 6 Phase B L5 confusion matrices from cached val logits at
  `runs/final/<tag>/logits/val.npz` into a single matplotlib figure with a
  shared right-side colorbar at `vmin=0, vmax=1` (row-normalized recall).
  Tiling existing PNGs would have preserved their individual colorbars
  (the very thing FX-06 is fixing) — re-rendering from logits is the
  right move.
- Per-panel subtitle: `acc = NN.NN%   most-confused: <true> -> <pred> (n=NN)`.
  Row labels = models; column titles = datasets; predicted/true axis
  labels on the bottom row / left col only.
- Output cross-checks PRD §4.8 finding text:
    * CIFAR-10 bird↔deer surfaces (TransNeXt-tiny: bird→deer n=183) ✓
    * MNIST 4↔7 surfaces (ResNet50 4→7 n=166; DenseNet121 4→7 n=168) ✓
    * MNIST 9↔1 surfaces (TransNeXt-tiny 9→1 n=134) ✓
  No drift between as-measured confusion data and the operator-locked
  Finding #7-text on this front.

- Files affected:
  - Final_Report/scripts/combine_confusion_grid.py (new)
  - Final_Report/figures/confusion/B_L5_grid.png (new)
  - Final_Report/figures/confusion/_grid_meta.json (new)
  - Final_Report/PROGRESS.txt (this entry)

- Learnings for next cycles:
  - Patterns:
    * `runs/final/<tag>/logits/val.npz` is the canonical cache for val
      logits. Files-on-disk schema: keys `logits` (shape [N, 10]) and
      `labels` (shape [N]). This is NOT a weight artifact — reading it via
      numpy is permitted under the weight-privacy contract (only
      `*.ckpt` / `*.pt` / `*.pth` / `artifacts/weights/` are forbidden).
    * 10×10 confusion matrix → row-normalize via
      `cm / cm.sum(axis=1, keepdims=True).clip(min=1)` (clip prevents
      0/0 if any true class has zero samples — defensive even though
      the 5000-sample val split always has all classes present).
    * Single-shared-colorbar pattern with matplotlib:
        `cbar_ax = fig.add_axes([0.94, 0.12, 0.015, 0.76])`
        `fig.colorbar(im_handle, cax=cbar_ax)`
      Pair with `fig.subplots_adjust(left=0.07, right=0.92, ...)` so the
      colorbar lives in the reserved margin. `tight_layout()` fights
      this — don't call it.
  - Traps:
    * I almost tiled the existing per-cell confusion PNGs (like I did for
      the calibration grids in Iteration 4). That would preserve each
      panel's individual colorbar, defeating the FX-06 goal. The
      calibration tiling was OK because reliability diagrams have no
      colormap; confusion grids do, and FX-06's "single shared colorbar"
      contract is load-bearing. Different mechanism per asset type.
    * The `subplots(..., gridspec_kw={"hspace": 0.32, "wspace": 0.22})`
      values were tuned to make room for the per-cell subtitle text
      (`ax.text(0.5, -0.22, sub, transform=ax.transAxes)`) without
      overlapping the next row. Adjust hspace, not the text y-offset,
      if the labels run too close.
