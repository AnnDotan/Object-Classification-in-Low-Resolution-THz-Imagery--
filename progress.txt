## Blur axis rescaled 2026-05-14 — visible degradation on 224×224
- Operator observation while reviewing the Phase C blur thumbs: all 5 levels looked
  identical to clean, no visible blur. Root cause: the pre-2026-05-14 kernel/sigma
  values (K=3..13, σ=0.80..2.30) were designed for native-size imagery (32×32);
  on the 224×224 upsampled tensor those kernels cover ~1–6% of image width and
  the Gaussian footprint is effectively a no-op.
- New curve (pixel-domain at 224×224, kernel = 2·⌈2.5σ⌉+1):
    L1: K=13, σ=2.5    (mild visible blur)
    L2: K=25, σ=5.0    (clear softening)
    L3: K=41, σ=8.0    (clearly blurred)
    L4: K=61, σ=12.0   (severe)
    L5: K=91, σ=18.0   (heavy smear)
- Files touched: `src/data/degradation_levels.py` (DEGRADATION_LEVELS table —
  ONLY `blur_kernel` and `blur_sigma`; low_res/noise/S&P/saturation unchanged),
  `CLAUDE.md` table, `README.md` table.
- Dashboard refreshed: `Final_Exp.json` rebuilt; 60 thumbs re-rendered with --force
  (30 Phase B all-axis cells + 30 Phase C blur-isolation cells). Phase A (clean)
  and the 120 Phase C cells with inactive blur (4 inactive axes return to identity
  per US-003) unchanged.
- Verification: pytest 21/21 ✓, determinism gate MSE=0 ✓.
- `degradation_levels_hash` rotates: cross-batch comparison against pre-2026-05-14
  runs that involved blur is invalidated.
- DOWNSTREAM CAVEAT (operator-accepted, option (א) from 2026-05-14 conversation):
  the 4 already-frozen winner JSONs (resnet50×{cifar10,mnist}, densenet121×{cifar10,
  mnist}) were tuned at the OLD L3 blur (K=7, σ=1.5 — essentially no-op). Phase B

- Learnings for next cycles:
  - Patterns: For new scripts/* entry points the repo convention is to
    prepend the repo root onto `sys.path` at module top
    (`_REPO_ROOT = Path(__file__).resolve().parents[1]; sys.path.insert(0, ...)`)
    before the first `from src...` import. `run_phase_a.py` lines 44-46
    show the canonical shape; without it, `python scripts/<name>.py`
    fails with `ModuleNotFoundError: No module named 'src'` even though
    `pytest` works (pytest auto-rootdirs).
  - Patterns: Torch-free CLI infrastructure should defer imports of
    torch / Lightning into the function body that actually needs them
    (`_resolve_run_cell`, `_resolve_oom_exception`). Combined with
    injectable parameters on the dispatch functions
    (`run_cell_fn=None, oom_exception=None`), the same module is
    both production-runnable and unit-testable without a torch dep.
  - Traps: mypy chokes when the same source file is reachable via two
    module names (`run_ralph_loop` and `scripts.run_ralph_loop`).
    Use `mypy --explicit-package-bases <files>` to avoid the
    "found twice" error. There is no `__init__.py` under `scripts/` —
    do NOT add one, the rest of the toolchain treats it as a flat
    script dir.
  - Traps: PRD §6.4 step 1 ("lr_backbone = lr_head / 10") composes with
    §6.3 verdict deltas, and ORDER MATTERS. The driver applies the
    ratio tighten FIRST, then the verdict-specific deltas; this means
    the overfitting branch's `lr_backbone ÷ 2` operates on the freshly
    tightened ratio, not the operator-supplied baseline. Failing to
    sequence them this way would produce off-by-10× retry LRs.
  - Traps: For mypy's `except` clause type-narrowing the lazy-loaded
    exception class must be hinted as `type[BaseException]` — the bare
    name resolves to `type` and the except clause is rejected as
    "must be derived from BaseException".
  - Helpful context: With US-005 closed, the next Ralph cycles can
    actually dispatch cells — US-006 (Phase A · resnet50) is the first
    GPU-gated execution US. The driver writes
    `runs/final/<tag>/NEEDS_FULL_FT` containing the verdict string
    (`failed_convergence` or `overfitting`) so the second-pass
    remediate-only mode can read the verdict back without re-running
    the pathology guard. Cells that succeed on retry have the
    sentinel removed automatically; cells that fail the retry get a
    `QUARANTINED_AFTER_RETRY` sentinel with body
    `second_failure:<verdict>` and are skipped on subsequent
    `--remediate-only` invocations.
