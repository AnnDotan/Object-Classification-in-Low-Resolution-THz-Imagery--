# Dashboard Implementation Notes

## What Was Created

### 1. **Basic Interactive Dashboard** (`generate_dashboard.py`)
A lightweight, fully self-contained HTML dashboard with:
- **Statistics Cards**: Total experiments, completed runs, models tested, best accuracy
- **Model Comparison Chart**: Bar chart comparing average and max accuracy by model
- **Degradation Level Analysis**: Performance across low_res=8, 16, 32
- **Accuracy Distribution**: Histogram showing distribution of achieved accuracies
- **Filterable Results Table**:
  - Search by run name
  - Filter by group (official, pilot, archive)
  - Filter by model
  - Sort by any column
  - Color-coded accuracy (green ≥60%, orange 50-60%, red <50%)

**File Size**: 33KB | **Render Time**: <2 seconds | **Dependencies**: Plotly.js (CDN)

### 2. **Advanced Dashboard** (`generate_advanced_dashboard.py`)
Extended dashboard with learning curve visualization:
- All features from basic dashboard
- **Top 6 Runs Display**: 
  - Ranked by validation accuracy
  - Click to view learning curve
  - Shows model, accuracy, and degradation level
- **Interactive Learning Curves**:
  - Dual-axis display (accuracy + loss)
  - Train/validation accuracy with markers
  - Loss curves toggleable via legend
  - Hover for epoch-by-epoch metrics
  - Dynamic updates when selecting different runs
- **Enhanced Layout**: Organized into sections (Overview, Learning Curves, Detailed Results)

**File Size**: 46KB | **Render Time**: <2 seconds | **Data**: Loads metrics from top 6 runs' metrics.csv

### 3. **Refresh Tool** (`refresh_dashboards.py`)
Convenience script that:
1. Generates run summary CSV from all experiments
2. Regenerates basic dashboard
3. Regenerates advanced dashboard
4. Reports success/failure status

**Usage**: `python refresh_dashboards.py` (after new experiments complete)

## Technical Architecture

### Data Flow
```
runs/ (experiment directories)
  ├── run_config.txt (parameters)
  ├── log.txt (training logs + best_val_acc)
  └── metrics.csv (per-epoch metrics)
       ↓
summarize_runs.py
       ↓
artifacts/tables/run_summary.csv (aggregated metadata)
       ↓
generate_dashboard.py → artifacts/dashboard.html
       ↓ (also loads metrics.csv for top 6)
generate_advanced_dashboard.py → artifacts/dashboard_advanced.html
```

### Technology Stack
- **Frontend**: HTML5 + CSS3 + ES6 JavaScript
- **Charting**: Plotly.js (via CDN - no local dependencies)
- **Data Format**: JSON (embedded in HTML via `json.dumps()`)
- **Styling**: Gradient backgrounds, responsive grid layout, dark mode ready

### Key Design Decisions

1. **Self-Contained HTML Files**
   - No server required
   - No build process
   - No additional dependencies beyond browser
   - Can be shared via email or GitHub
   - Works offline after generation

2. **Embedded JSON Data**
   - All experiment data embedded in HTML
   - No external API calls
   - Fast loading and responsive interactions
   - Reduces distribution complexity

3. **Plotly.js for Charting**
   - Interactive tooltips and zoom
   - Professional appearance
   - Works across all modern browsers
   - Loaded from CDN (minimal file overhead)

4. **Dual Dashboard Approach**
   - Basic: Fast load, essential metrics only
   - Advanced: Learning curves for deeper analysis
   - Users pick based on their needs

In the script's HTML template, update gradient colors:
```css
background: linear-gradient(135deg, #667eea 0%, #764ba2 100%);
```

### Adding New Metrics
Edit the aggregation functions in generate_dashboard.py:
```python
# Add to model_comparison dict
'new_metric': config.get("new_metric", ""),
```

### Filtering Options
Add new filter dropdowns in the HTML section:
```html
<select id="newFilter">
    <option value="">All Options</option>
    <option value="option1">Option 1</option>
</select>
```

```javascript
const matchNewFilter = !newFilter || run.field === newFilter;
```

## Maintenance

### Regenerating Dashboards
After new experiments:
```bash
python refresh_dashboards.py
```

This will:
- Scan runs/ directory recursively
- Extract latest metrics
- Update both dashboards
- Takes <30 seconds typically

### Troubleshooting

**Issue**: New runs not appearing
```bash
# Check that runs have required files
ls runs/*/run_config.txt
ls runs/*/log.txt

# Regenerate summary
python src/tools/summarize_runs.py

# Update dashboards
python refresh_dashboards.py
```

**Issue**: Learning curves not showing
- Check that runs have metrics.csv
- Verify metrics.csv has valid epoch/loss/acc columns
- Only top 6 runs show curves (design limitation)

**Issue**: Incorrect accuracy values
- Check run_config.txt exists in run directory
- Verify log.txt contains "best_val_acc=" line
- Look for training errors in log.txt

## Performance Optimization Notes

### Why Embed Data?
- Eliminates API calls and latency
- Makes dashboards shareable
- Works without server

### Why Load Only Top 6 Learning Curves?
- Reduces HTML file size
- Improves initial render time
- Most users focus on best runs anyway
- Can be tuned: change `[:6]` to `[:N]` in script

### Why Use Plotly.js?
- Rich interactivity (zoom, pan, hover)
- Small library footprint (loaded from CDN)
- Professional appearance
- Works across all browsers
